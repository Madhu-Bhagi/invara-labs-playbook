# Engineering Reference

> *"Knowledge becomes valuable when it is organised, accessible, and reusable."*

---

# Overview

Engineering Reference provides the supporting knowledge that engineers use to understand concepts, technologies, patterns, and practices throughout the software development lifecycle.

Unlike the Engineering Principles, which explain **why** engineering decisions are made, the Engineering Playbooks, which describe **how** engineering activities are performed, and the Engineering Standards, which define **what** must be consistently followed, the Engineering Reference serves as the organisation's engineering knowledge base.

It captures reusable information that engineers consult while designing, building, testing, deploying, and operating software systems.

The goal is to make important engineering knowledge easy to discover, understand, and apply.

---

# Purpose

The Engineering Reference exists to:

- Build a shared engineering knowledge base.
- Document common engineering concepts.
- Explain architectural patterns and design approaches.
- Define engineering terminology.
- Capture reusable technical guidance.
- Reduce duplicated research.
- Preserve organisational knowledge.
- Support continuous learning.

Rather than prescribing how work should be performed, the Reference provides the context and information that enable better engineering decisions.

---

# How to Use This Reference

Engineers should use the Reference whenever additional context or supporting knowledge is needed.

Reference material complements the Principles, Playbooks, and Standards by providing background information rather than procedural guidance.

Typical reference content includes:

- Engineering concepts
- Design patterns
- Architectural styles
- System integration patterns
- Technology comparisons
- Performance techniques
- Security concepts
- Testing strategies
- Cloud and infrastructure guidance
- AI engineering knowledge
- Glossaries and terminology
- Frequently asked questions (FAQs)

Reference documents should remain objective, concise, and easy to navigate.

# Characteristics of Good Reference Material

Reference documentation should be:

- Accurate
- Technology-neutral where possible
- Well organised
- Easy to search
- Concise
- Continuously maintained
- Supported by examples
- Cross-referenced with related documents

Reference material should explain concepts without prescribing implementation unless appropriate.

# Relationship to Engineering Knowledge

Engineering Reference is one component of the Engineering Operating Model.

```text
Engineering Principles
        │
        ▼
Engineering Playbooks
        │
        ▼
Engineering Standards
        │
        ▼
Engineering Reference
        │
        ▼

```

Together they provide:

- **Engineering Principles** — Why engineers think.
- **Engineering Playbooks** — How engineers work.
- **Engineering Standards** — What engineers follow.
- **Engineering Reference** — What engineers consult.
- **Engineering Examples** — How excellence looks in practice.

Together, these resources create a comprehensive engineering knowledge system that supports consistent decision-making, continuous learning, and long-term organisational growth.
